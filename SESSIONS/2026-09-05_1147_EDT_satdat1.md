### Prompt

### Response

**Diagnosis, in the order it actually went.** Everything tested in isolation worked —
hooks firing (`trace.log` live), Hammerspoon's Apple Events permission (exit 0 from
`hs.task`), the title poll by hand (six windows, glyphs intact), `claudeCwdFromTitle`
against the real titles, `hs.spaces.windowSpaces` returning real Space ids, and every
config value sane. So the fault had to be between them.

Reading the module's live internals through `dd.redraw`'s upvalues gave the answer:
**`sessions = table(0)` while `claudeHooks = table(2)`.** Those are assigned four lines
apart in one callback, so the callback was running and the AppleScript was returning
nothing.

Extracting `CLAUDE_TITLE_SCRIPT` and running it standalone:

    script error: Expected “,” but found class name. (-2741)

at `id of current window`, inside `tell application "iTerm"`. **iTerm is not installed
here.** AppleScript compiles the whole script before running any of it, so
`if application "iTerm" is running then` — a runtime test — cannot prevent a
compile-time failure. The Terminal half never ran. Cut the block out and the same script
returns all six windows.

**Fix: D94, Task #21.** The script became four literals assembled by
`claudeTitleScript()`, with the iTerm block included only when
`hs.application.pathForBundleID` finds the bundle (it returns `""`, not `nil`, when
absent — both are treated as missing). Re-checked every 60s so installing iTerm needs no
reload. D65's one-task rule is untouched.

**Verified live.** Both assembled variants were written out and run: no-iTerm compiles
and returns six windows; with-iTerm still fails *here*, correctly, because iTerm is
genuinely absent — the reassembly is byte-faithful to the original literal. After
`hs.reload()` the module's `sessions` table went **0 → 3**: `MODIS_L2 idle`,
`Git_Repos idle`, `claude-config working`.
